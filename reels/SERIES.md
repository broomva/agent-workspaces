# Agent Workspaces: the reel series (Act I)

The data lives in `series.json`. This file explains it and is the brief every writer and reviewer works from. BRO-3817.

## What one reel is

```
0 ─────────── h ──────────────────────────── h+b ─────────── h+b+c ── +1.5 s
│ spoken hook │ keynote body slice             │ spoken CTA     │ hold  │
│ + screen    │ (River audio, the reel's own   │ + end card     │       │
│   hook      │  visuals, word-by-word CWI      │ (Part N/5,     │       │
│ (cold open) │  captions)                      │  next, keyword)│       │
```

- `h` is the spoken hook: a new River line, generated by `reels/tts.mjs` from `spokenHook`.
- `b` is the keynote slice from `body.start` to `body.end` in `deck/narration/river.mp3`. It is never re-voiced, so the keynote and the reel say the same words.
- `c` is the spoken call to action, `funnel.spokenCta`, the same line in every part.
- The voice is the same River stock voice as the keynote. Every reel shows the `AI VOICE` label, and the post carries `postCopy.disclosure`.

## The hook rules (from the reel-loop skill)

Every part has to pass these. Reviewers score against them.

- **H1.** Frame 0 is a complete thought: the title or the screen hook is readable before anything moves.
- **H2.** The spoken hook is under 12 words and opens a gap, either a question or a concrete stake. A definition is not a hook.
- **H3.** The screen hook adds a second hook and does not repeat the spoken line.
- **H4.** Concrete beats abstract: counters, folder names, layer names.
- **H5.** Something changes on screen before 1.5 s.
- **H6.** The body pays off the hook before the last 20 % of the runtime.

No claim may go beyond what the keynote slice says. The Act I review on 2026-10-27 removed unsourced marketing lines, and that standard still holds.

## Continuity

- Each end card names the next part (`next`). The next part's spoken hook picks that thread up.
- Part 3's first keynote line, "Six layers help organize that continuity", lands straight after Part 2's closing word, "continuity".
- Every part ends on the same keyword ask, so the funnel is identical across the series. Comment WORKSPACE and the DM delivers the Act I playbook (BRO-3554; the sender is BRO-3815).

## Writers

- Each writer owns `reels/<reel>.html` and `reels/captions/<reel>.*`. Nothing else.
- `series.json`, `render.mjs`, `tts.mjs` and the shared overlay belong to the series PR. If you need a change there, ask for it; do not edit them.
- New reels start from `r01-folder.html`'s structure. Port the scene's own deck visual from `deck/index.html`, and keep `renderAt(t)` a pure function of time.
- Layout follows the deck's vertical contract (`deck/vertical.json`, BRO-3566). Check every render with `--safe`, and check the content-engine vertical layout gate if you have it. Nothing important goes in the top 277 px or below the caption band.
- Quality bar before handing back:
  - a full render;
  - a contact sheet;
  - stills at 0.0 s, 1.5 s, the body midpoint and the end card;
  - `bun run check` green;
  - each H1–H6 marked pass or fail, with the frame that shows it.

## Post copy

`postCopy` in `series.json`. The first line is the spoken hook. Then the part number, the keyword ask and the guide link, then the AI-voice disclosure and hashtags. Trial Reels go through reel-loop's `publish` with `trial_params` once the owner approves each post.
